# ABI proof ledger

Updated: 2026-09-09

This ledger separates software portability from neural transplantation. A
result in one row must never be promoted into another row without its own
registered evidence.

## Exact distinctions

### Runtime-owned copy/paste

The package is immutable and recipient-independent. A fixed capability-blind
interpreter executes its canonical semantics, while a host codec realizes the
result through the host output interface. Removing the package removes the
behavior; restoring identical bytes restores it. This is useful capability
portability, analogous to portable code plus an instruction-set runtime.

### Native neural transplantation

The same package changes a recipient's neural computation through a fixed
capability-blind neural backend, with no capability-specific optimization, and
the recipient produces teacher-equivalent behavior. The backend may not be an
external answer solver. R8 and R9 did not establish this.

R11 establishes a narrower but positive construction boundary: its package is
a learned neural transition state, a zero-parameter neural ISA executes it,
and pre-capability frozen codecs inject the state into heterogeneous native
output heads. Exact frozen-package replay passes. The learning substrate is
ABI-native, not a conventional pretrained LLM, and the package is not
internalized into recipient transformer blocks. R11 therefore promotes
ABI-C4b but not ABI-C4, ABI-C5, or foreign-teacher extraction.

R13-B establishes ABI-C4c for an exhaustively enumerable finite family. A
conventionally trained Qwen source exposed the complete 24-entry transition
table, and the frozen R11 stack executed the canonical package exactly. Because
native source/package agreement was only 372/2,048, this is not ABI-C4
teacher-function copying. Because the probe set is the entire capability
specification, it is not evidence of non-enumerable or general knowledge
extraction.

R14 tested ABI-C4d without atomic probes. The query/evaluation ratio was
`256 / 4,642,668,576` per capability, and evaluation used unseen depths and
order counterfactuals. One capability was recovered exactly on all 11,000
registered oracle rows, but two were not. This is positive mechanism evidence
inside a failed reliability certification; it does not promote ABI-C4d.

R15A establishes ABI-C4e for a learned weight-delta interface. The extractor
received no behavioral queries or answers and operated in a pivot-root capsule;
all eight fresh packages were exact and all recipient rows replayed byte-for-
byte. The source capabilities were deliberately installed through complete
atomic supervision, so R15A does not establish pre-existing knowledge
extraction, semantic labeling, English/domain transfer, or Track A equality.

### Teacher-quality English/domain extraction

An open-weight source is diagnosed, English and domain knowledge are separated,
the selected information is packaged, the source is absent at inference, and
the resulting LayerCake passes teacher-relative generation-quality gates. No
existing ABI release establishes this.

## Promotion rule

R10 promotes only ABI-C4a, the bounded runtime component. R11 promotes ABI-C4b,
the bounded synthetic neural-ABI construction. R13-B promotes ABI-C3 and
ABI-C4c only for local, exhaustively enumerable capability canonicalization.
R14 promotes no claim because its registered three-capability gate failed.
R15A promotes ABI-C4e only. None promotes ABI-C4 teacher-behavior copying,
ABI-C5, ABI-C6, ABI-C7, or ABI-C8. Foreign-teacher behavioral transplantation
and English/domain quality remain separate registered lines.
