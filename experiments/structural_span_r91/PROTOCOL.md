# R91 preregistration: structure-invariant neural span package

R90 showed that the frozen R88 package transferred a real signal to the
broader R60 reasoning surface (55/100 versus 0/100 for both the prior endpoint
and random bridge) but depended on the training corpus's candidate-list
layout. R91 changes the normalization architecture, not the teacher evidence,
host, evaluator, or package size.

R91 starts a fresh R88-topology bridge from random initialization over the
unchanged 8,129 teacher-labeled records. Each record's four opaque codes are
renamed bijectively and its two supplied transitions are rendered through one
of 16 meaning-preserving structural forms, six neutral outer interfaces, and
four candidate-list placements. Candidate order is randomized. The response
is always the unchanged renamed teacher response. These transformations add no
new answer claim, teacher output, source logit, source activation, or domain
fact; generated normalization text is not packaged.

The R76 LayerCake host is frozen. Only the 530,050-parameter joint-span bridge
is trained on CUDA for 4,000 successful steps, batch 32, seed 91,001, AdamW,
learning rate 0.001, and weight decay 0.01. Every imported record must be seen.
All host execution must remain physically sparse.

After training, the checkpoint is frozen and bound before the disclosed R60
development diagnostic. That diagnostic uses all 100 reasoning rows, the
stored R60 source comparison, and a deterministic random bridge. It passes
only at 95/100 candidate quality, 95% source retention, at least +50/100 over
the old R60 endpoint, random no higher than 35/100, zero collapse, exact sparse
execution, teacher absence, and unchanged artifacts.

R60 is disclosed and cannot promote R91. A development pass authorizes exactly
one new prospective catalog built from held-out syntactic forms, wrappers,
identities, and token widths after the candidate is sealed. A development
failure closes this structural-normalization design. The full ABI moonshot
remains `OPEN`.
