# R104: evaluator contract, English control, recipient/interface suitability

Registered 2026-11-10 before new model execution. The user authorized evaluator
validation, control qualification, the conditional bounded comparison and public
publication. This is a zero-training diagnostic, not capability acquisition.
R103 remains a failed prerequisite with its original scores and evaluator intact.

## Evaluator prerequisite and unchanged gates

The R98/R103 literal screen has an observed false positive on a future conditional
("as soon as the details are confirmed"). R104 prospectively replaces only that
unscoped contradiction rule with a narrow clause-local rule. It accepts the
listed if/when/once/until/before/after/as-soon-as subject patterns; commas,
conjunctions and sentence boundaries end their scope. A separate present/past
approval assertion or guaranteed future approval still fails. Unsupported
conditional grammar is not automatically exempted. This is NOT a semantic parser.

Other checks are retained or strengthened: the requested 120-word bound is now
enforced (formerly 180); unsupported weekdays fail; summary/tone requests require
the registered two-or-three-sentence proxy. Literal coverage, unknown identifiers,
invented numbers, task form and repetition checks remain. All raw rows retain
both the old screen (descriptive only) and the new screen. No old decision changes.

Before model work, require exact agreement on all 155 deterministic fixture cases:
eight-task positive/negative examples, omissions, foreign identifiers, invented
numbers/days, length, repetition, task form, and conditional/assertion minimal
pairs. Raw case text and expected/observed decisions are frozen. These are
author-specified formal-obligation tests, NOT independent human fluency labels,
not a calibrated semantic-quality estimator, and not a broad validity proof.
The observed scorer limitations remain claim limitations even if fixtures pass.

Control qualification remains >=44/48, >=5/6 for EVERY one of eight tasks, zero
collapse and zero budget-truncated responses. No thresholds are lowered. Only
raw autonomous text is scored; no cleanup, repair, retrieval, answer selection,
oracle prefix or LLM judge. Qualification means this finite mechanical contract,
not a generally fluent, human-qualified English model.

## Conditional comparison

Only after qualification, run the unchanged R76 parent, R100 full-model control,
R99 FP32 LoRA and adapter-distillation controls, plus Qwen, each on all 48 new
comparison cases under BOTH native and Task/Response interfaces. No training.
Native recipient = raw user prompt plus newline. Native Qwen = chat template.
Task/Response is the identical plain completion string for every model. Inherited
acquisition costs and parameter scale differ; Qwen is a feasibility control, not
a matched-size architecture or efficiency comparator. LoRA/distillation/full-model
labels identify retained conventional controls, not new matched training here.

Two primary within-checkpoint contrasts: native-minus-Task/Response for parent
and full-model control. A positive 97.5% paired bootstrap lower bound supports
interface sensitivity for that checkpoint; 10,000 resamples, seed 104001. Also
report 95% intervals. Other contrasts are descriptive. A recipient's bounded
screen requires the same absolute gates plus control-relative 95% lower bound
>=-0.10, on the same paired comparison cases. The native control must also pass
the comparison screen; otherwise qualification transportability is unresolved.

Report all ten cells, task floors, omissions, contradictions, format, repetition,
truncation, literal legacy/new disagreements, raw resource and information costs.
No CPU inference superiority, English product, ABI acquisition novelty or broad
moonshot certificate can be promoted by this experiment.

## Custody, limits and attribution

Freeze and commit code/protocol/tests, evaluator cases and audit, both populations,
all checkpoint/tokenizer bytes, loader, external host sources, source inventory,
and environment before execution. Zero optimizer steps, copied source parameters,
new checkpoints, stored logits/activations or trained bridges. Preserve historical
acquisition information and costs. Recipients stay GPU FP32 with TF32 off.
Greedy output, max640 tokens, 1024 context precheck. Physical route traces must
contain only the requested cake and its six matching adapters at each decode.

90-minute pilot bound, 25 minutes/process, <=144 control and <=384 recipient
calls, <=1GiB new evidence and >=20GiB free at start. Stop on evaluator,
qualification, context, integrity, numerical, route or resource failure. Preserve
partial evidence; no automatic retry. Strictly recompute from raw IDs/text and
hashes, not stored scientific booleans. Exercise hostile verifier mutations.

Evaluator/control failure belongs to the prerequisite. A qualified control with
failed recipients supports limitations of these checkpoint/acquisition/interface
combinations only. Unexpected route/path behavior is an unlocalized integration
finding until separately localized. Neither licenses a native LayerCake defect
claim. LayerCake source and its existing evidence remain unchanged.

Weight-space editing is a possible future competing acquisition method, NOT an
additional arm or package-contract change authorized by R104. See the separate
[research assessment](../../docs/WEIGHT_SPACE_RESEARCH_2026_11.md).
