# R69 preregistration: answer-stem reasoning acquisition

R67 and R68 established the same source-interface failure: Phi expands into a
long derivation and often reaches the token ceiling before its terminal class.
R69 changes the interaction shape. Each prompt supplies a three-hop fictional
class chain and ends with an incomplete answer stem. The source must complete
only the derived terminal category code. The correct code is not present in the
answer stem and must be inferred from the premises.

The 2,000 search-only prompts use compact unique nonce labels, eight natural
premise phrasings, four answer stems, a 24-token ceiling, contains-conclusion
evaluators, empty domain labels/claims, and no real-world facts. Code and catalog
are committed before source access. Pinned Phi identity, CUDA execution,
provenance, accounting, segregation, and candidate inaccessibility remain
unchanged.

At least 1,800/2,000 source rows must pass. The source archive must also have
zero collapse under post-hoc authoritative tokenization. If it passes, only
passing search records may be composed into v3 segregated training material.
R69 is acquisition evidence only and cannot certify a host or the moonshot.
