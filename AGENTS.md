## Permanent claim rules

- Never call domain discovery exhaustive.
- Never call transfer from a non-LayerCake teacher "lossless." Certify measured
  source-relative generation quality. Reserve "lossless" for verified exact
  LayerCake package/archive/tensor transfer.
- Never infer a semantic label from tensor location without a validated
  intervention and held-out behavioral gate.
- Runtime token IDs are authoritative; character estimates are not token
  counts.
- Account prompts, unique UTF-8 bytes, teacher outputs, tokens, logits,
  activations, copied parameters, learned substrate, bridges, disk, RAM, time,
  and hardware separately.
- "Minimum" means lowest passing preregistered tested nested budget paired with
  the largest lower failing budget. It is not a global minimum.
- Keep exact byte/tensor identity separate from bounded semantic retention.
- "Pure English core" is a bounded corpus and behavioral isolation claim. Do
  not claim that finite tests prove literally zero world knowledge in weights.
- `.abix` contains teacher material and is never a deployable cake.
- A new model, catalog, host, or package is unqualified until the same final
  teacher-free LayerCake clears functional, isolation, identity, CPU speed,
  TTFO, RSS, and three-seed/fresh-host gates.
- A LayerCake regression may be recorded only when the exact sealed native
  LayerCake control fails within its bound scope. An ABI failure before
  LayerCake invocation remains ABI. For a broader installed-candidate quality
  scope, require a passing same-topology known-good or oracle payload before
  localizing a miss to ABI; otherwise classify it as unresolved ABI
  acquisition versus expanded host capacity.
- No ABI candidate inherits the sealed LayerCake checkpoint's speed, quality,
  TTFO, or memory evidence. The same integrated candidate must rerun every
  promoted gate.

## Development rules

- Preserve all negative evidence. Never overwrite, reset, or mass-delete the
  experiment ledger.
- Pin new source revisions and hash exact source weights.
- Use disjoint search, validation, and final-test splits. Final data cannot
  select prompts, budgets, checkpoints, sources, or repairs.
- Exclude unselected domain records from composed acquisition material.
- New successor training bundles must use segregated v2 records, a validated
  user-governed domain ontology, and a passing core/domain segregation manifest.
- English-core records may teach linguistic form only. They cannot carry
  specialist labels or claims or introduce declared unsupplied facts. Use
  abstract/nonce material, supplied non-domain context, interpersonal
  pragmatics, and domain-free instructions.
- Specialist facts, procedures, code, and domain-labeled calculations belong
  in separately selectable domain artifacts. Quarantine unknown,
  cross-domain, and disputed records.
- Preserve record-level provenance; multi-source conflicts fail closed.
- Before a new teacher artifact can authorize acquisition training, run
  `abi.teacher_artifact_adequacy_audit`. Retain authoritative generated token
  IDs and finish reasons; reject or independently revalidate ceiling-terminated
  outputs; use content-specific functional evaluators; record extraction time
  and exact device identity; include at least 100 distinct passing records per
  required capability; and require promotion-eligible selection. Generic
  hygiene checks do not establish prompt grounding or task correctness.
- Test tampering, wrong source/key, leakage, duplicate identifiers, traversal,
  non-nested budgets, teacher-at-inference, inactive execution, and
  finite-suite claim inflation.
- Do not modify files bound by a frozen certificate. Create a versioned
  successor and preserve the prior certificate.
- Do not repair the measured generalization failure with more template or
  symbolic special cases. A successor needs broad acquisition and held-out
  natural-language generalization.
- Do not substitute an ABI-local ONNX transformer, router, or decoding runtime
  for the exact LayerCake execution host. Use the sibling repository as an
  immutable external control and consumer; never edit it from ABI work.
- Before another acquisition run, execute the native LayerCake positive
  control, capability-naive receiver, bridge-only, and native-payload-same-path
  controls required by the attribution contract. Before promotion, also run
  the actual bridge-only control and shuffle the same reference-adequate ABI
  artifact. A shuffled version of an already failing artifact is
  non-informative and cannot establish transfer causality.
- V80 executed the V79 successor same-topology direct-target oracle and failed
  at 4/28 with one collapse. Before any expensive English extraction or
  payload run, execute only the preregistered balanced-capability V81 oracle
  control justified by V80's measured stream imbalance. V81 failed. Do not
  call later installed-candidate misses ABI-only. V82 completed the shared-
  initialization transformer-student separator and both paths failed. The next
  work is ABI source-information expansion with construction-guaranteed English
  segregation. V83's Phi-3 preflight failed, so only a newly preregistered
  successor source/artifact may continue; any qualified artifact goes first to
  the matched transformer acquisition screen.
- A bridge must be parameter-, token-, byte-, time-, RAM-, and hardware-
  accounted. If the bridge-only control retains English, transfer causality
  fails because the bridge may have relearned the capability.
