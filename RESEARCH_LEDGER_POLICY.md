# ABI research-ledger policy

Status date: 2026-08-03

## Purpose

ABI preserves negative evidence, superseded protocols, implementation changes,
and the artifacts needed to interpret them. Preservation does not require
placing every generated byte into ordinary Git history.

## Tracked in ordinary Git

- source code and tests;
- human- and machine-readable governance;
- protocols, amendments, incidents, decisions, certificates, and compact raw
  evidence;
- compact catalogs and partition manifests;
- generators and exact regeneration commands; and
- content-addressed manifests for large local or externally stored artifacts.

## Preserved locally but not ordinary Git blobs

- model weights and checkpoints;
- teacher-output and activation caches;
- raw runtime ledgers and logs;
- generated catalogs at least 1 MiB that were not already tracked at the time
  of the current historical consolidation; and
- other large reproducible artifacts explicitly covered by `.gitignore`.

These files must not be deleted during repository cleanup. Their manifest must
record relative path, exact byte size, SHA-256, retention state, and aggregate
counts. Restoration is valid only when the exact hash matches.

## Current manifest

`ABI_LOCAL_RESEARCH_ARTIFACTS_MANIFEST_V1.json` binds every historical
generated catalog of at least 1 MiB and explicitly distinguishes previously
tracked files from content-addressed local-only files. It is generated with:

```powershell
C:\Python310\python.exe -m abi.research_artifact_manifest `
  --repository-root . `
  --status-date 2026-08-03
```

## Release boundary

A Git-clean research repository can still depend on local evidence. It may not
be called self-contained or independently reproducible unless every required
artifact is included in the release, regenerated from pinned inputs, or
retrieved from a content-addressed published location. The manifest states
preservation and identity; it does not by itself prove public availability.
